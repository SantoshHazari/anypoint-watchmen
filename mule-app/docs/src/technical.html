1. What you are setting up

Watchmen is a small program (a "Mule application") that runs on a computer, wakes up every hour, reads information from your company's MuleSoft Anypoint Platform account and shows it on a web page.

Anypoint PlatformYour MuleSoft account in the cloud
➜
WatchmenRuns on your PC or a server. Reads data every hour and stores it in a small local database.
➜
YouOpen http://localhost:5050 in a browser. Optionally receive alert emails.
It is safe to try. Watchmen only reads from Anypoint. It cannot deploy, change or delete anything in your MuleSoft account.

How long it takes

What you will have at the end

  • A dashboard in your browser with six tabs: Overview, Alerts, Audit log, Inventory, Jobs, Settings.
  • Data refreshed automatically every 60 minutes while Watchmen is running.
  • Optional: alert emails to a list of people you choose.

3. Step by step

1

Install the software

  1. Install Java 17. Afterwards, open a terminal (Windows: press Start, type cmd) and run java -version. You should see 17.x.
  2. Download and unzip Anypoint Studio. Start it, choose a workspace folder when asked, and sign in with your MuleSoft account if prompted.
2

Create the Anypoint "robot login" (Connected App)

Watchmen logs in to Anypoint by itself, without a person. For that, an administrator creates a Connected App:

  1. Sign in at anypoint.mulesoft.com and open Access Management Connected Apps Create app.
  2. Name it Watchmen Dashboard. Choose "App acts on its own behalf (client credentials)".
  3. Click Add Scopes and add read-only scopes for: usage reports (Usage Viewer), audit log (View Audit Logs), organisation and environments (View Organization, View Environment), Runtime Manager applications (read/view applications) and API Manager (view APIs). Select the root business group and all environments.
  4. Save. Open the app and use Copy Id and Copy Secret. Send them to the person installing Watchmen securely, for example through a password manager, never by plain email or chat.
  5. Find the Organization ID: Access Management Business Groups, then click the top (root) group. The ID is shown on that page and in the browser address bar.
Scope names vary slightly between Anypoint versions. If a later step fails with "403 Forbidden", the Connected App is missing a scope. Ask the administrator to add the one for that area (usage, audit, applications or APIs).
3

Open the project in Anypoint Studio

  1. In Studio: File Import… Anypoint Studio Anypoint Studio project from File System Next.
  2. For Project Root, browse to the anypoint-watchmen folder. Click Finish.
  3. Wait until the bottom-right progress bar finishes (the first time, Studio downloads components; this can take several minutes).
4

Give it the credentials

The credentials are not typed into any project file, so they can never be shared by accident. They are given to Studio when it starts the app:

  1. Run Run Configurations…. In the left list, under Mule Applications, select anypoint-watchmen. If it is not there, double-click Mule Applications to create it and tick the project.
  2. Open the Arguments tab and add these three lines to the arguments box, replacing the parts in angle brackets with the values from Step 2:
-M-Danypoint.client.id=<your client id>
-M-Danypoint.client.secret=<your client secret>
-M-Danypoint.orgId=<your organization id>
  1. Click Apply.
5

Start it and open the dashboard

  1. In the same window click Run. Alternatively, right-click the project, then Run As Mule Application.
  2. Watch the Console at the bottom. When you see DEPLOYED next to anypoint-watchmen, it is running.
  3. Open a browser at http://localhost:5050.
The first automatic data collection starts about 1 minute after start-up and then repeats every 60 minutes. You do not have to wait. Open the Jobs tab and click Run collect_all, then refresh after about 30 seconds.

Watchmen only collects while it is running. If the computer sleeps or Studio is closed, collection pauses. On the next run, the audit log continues from where it stopped, looking back up to 24 hours by default.

6

First-run checks (do these once)

a) Check the job worked. In the Jobs tab, the latest collect_all row should say success. If it says partial or failed, the Result column says which part failed. See Troubleshooting.

b) Confirm the usage meter names. Anypoint names each usage measurement (a "meter"). Only some of the names in Watchmen's settings file are confirmed. To see the real names for your account, open this address in the browser while Watchmen is running:

http://localhost:5050/api/usage/meters

Then, in Studio, open src/main/resources/config/entitlements.json. For each line whose "verified" is false, set meter and measurement to the matching names from that list and change verified to true. Ask your MuleSoft account team if a name is unclear.

c) Enter the contract details. In the same file, set the contract section (id, start, end as YYYY-MM) and check every limit against the invoice.

d) Restart the app (red stop button, then Run again) so the changes take effect, and run collect_all once more.

4. Optional: email alerts

  1. In src/main/resources/config/app.yaml, under email:, set enabled: "true", from: to the sending address and smtp.user: to the account username. Gmail defaults are already filled in (smtp.gmail.com, port 465).
  2. Add the email password as one more run argument (Step 4). For Gmail this must be an App Password created in the Google account's security settings: 
    -M-Demail.smtp.password=<app password>
  3. Restart, then open the dashboard Settings tab, enter the recipients (one per line) and click Save settings.
Emails list every new or escalated alert since the previous email. If sending fails, Watchmen tries again on the next run, so nothing is lost.

6. Troubleshooting

What you seeWhat it means / what to do
App will not start: "Couldn't find configuration property value for key anypoint.client.id"The run arguments from Step 4 are missing or mistyped. Each line must start with -M-D.
"Address already in use" / port 5050Another program uses port 5050. Change http.port in app.yaml (for example to 5051) and use that in the browser address.
Jobs tab: failed with 401 or "no access_token"Client ID or Secret is wrong, or the Connected App was deleted or its secret regenerated. Re-copy them (Step 2).
Jobs tab: 403 Forbidden on usage, audit, apps or APIsThe Connected App lacks a scope for that area. The administrator adds it. Other parts keep working meanwhile.
Some meters listed as failed, or showing 0The meter name in entitlements.json is not right for your account. Do first-run check 6b. Remember Anypoint usage data is about 3 days behind.
Audit log tab is emptyNormal if nobody changed anything significant recently: routine events are deliberately ignored. Check the Recent audit polls table shows success.
No emails arriveCheck email.enabled is "true", recipients are saved, and the password argument is set. The Studio Console shows "Alert email failed: …" with the reason. Check spam folders too.
Dashboard shows "API unreachable"Watchmen is not running. Start it again in Studio (Step 5).

Studio's Console shows everything Watchmen does. Lines starting with watchmen. are the most useful. When running outside Studio, the same lines go to logs/anypoint-watchmen.log.

7. Running on a server or in the cloud

Running in Studio on a laptop is ideal for trying Watchmen out. For continuous monitoring it should run somewhere that is always on. Your IT or MuleSoft team can do this:

Option A: CloudHub 2.0 (recommended)

  • Deploy the app from Studio or Runtime Manager to a small (0.1 vCore) replica.
  • Enter the credentials in Runtime Manager → Properties and mark them secure.
  • Use a PostgreSQL database instead of the built-in file database, which does not survive restarts on CloudHub. Set db.url, db.driver (org.postgresql.Driver), db.user, db.password.
  • Note: one Watchmen replica consumes a small amount of your own vCore entitlement.

Option B: an on-premises server

  • Install a Mule 4.8 runtime (or Studio) on an always-on server with Java 17.
  • Build the package with mvn clean package and copy the .jar from target/ into the runtime's apps folder.
  • Pass the same -M-D… values when starting the runtime.
  • Keep the dashboard on the internal network: it has no login yet.

Security notes

  • Never put the Client Secret or email password in any file in the project. Use run arguments or secure properties only.
  • If a secret is ever shared by mistake (email, chat, a document), ask the administrator to regenerate it in the Connected App.
  • Give the Connected App read-only scopes only. Watchmen needs nothing else.

9. Glossary

TermPlain-language meaning
Anypoint PlatformMuleSoft's website and cloud service where integrations and APIs are built, deployed and managed.
Anypoint StudioThe free desktop program used to open and run Mule projects such as Watchmen.
Mule applicationA program that runs on the Mule runtime. Watchmen is one.
Connected AppA "robot" login in Anypoint that a program uses instead of a person. It has a Client ID and a Client Secret.
Client ID / Client SecretThe username and password of the Connected App.
Organization IDThe unique ID of your company's top-level Anypoint account.
Business groupA sub-division of the Anypoint account, such as a team or department.
EnvironmentA separate space such as Sandbox or Production inside a business group.
EntitlementSomething the contract allows a fixed amount of, such as 280 Mule Flows.
MeterAnypoint's name for one thing it measures, such as the number of flows or messages.
High watermarkBilling on the peak amount reached, for example the most flows running at once.
DrawdownA pool used up over the contract period, for example 47 million messages in total.
Audit logAnypoint's record of who changed what, and when.
JobOne collection run. collect_all runs every hour; others can be started from the Jobs tab.
localhost:5050"This computer, door number 5050": the address of the dashboard while Watchmen runs on your machine.
Run argument (-M-D…)A value handed to the app when it starts, used here to pass secrets without saving them in files.
